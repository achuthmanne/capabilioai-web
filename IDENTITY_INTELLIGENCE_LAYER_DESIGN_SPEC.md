# Identity & Intelligence Layer — Design Spec

Sub-spec of `EXECUTIVE_PATH_DESIGN_SYSTEM.md` (Module 16 — Executive Profile, Module 14 — Brand Studio, Module 13 — Executive Analytics, Module 15 — Inbox), plus Notifications and Settings, new additions. Sibling to `STARTUP_WORKSPACE_DESIGN_SPEC.md`, `FUNDING_HUB_DESIGN_SPEC.md`, `EXECUTIVE_INTELLIGENCE_LAYER_DESIGN_SPEC.md`, and `ECOSYSTEM_LAYER_DESIGN_SPEC.md` — inherits the same shell, tokens, and conventions from Startup Workspace §1.

Design-spec only, per explicit instruction — no frontend code in this pass.

**This spec replaces `AuthorityProfile.jsx` in place.** That file was already identified in the original `EXECUTIVE_PATH_DESIGN_SYSTEM.md` audit as broken in production — it calls Firestore functions (`doc`, `updateDoc`, `arrayUnion`, `arrayRemove`) that were never imported into this Supabase app, so Follow, Create Post, and Booking Request all throw a `ReferenceError` today. Executive Profile below is the real redesign that fixes that, not an additional parallel profile page.

## 0.1 Positioning

The tell that guards every screen in this spec: a resume lists what you did; LinkedIn performs what you did for an audience; this system verifies what you did and lets AI explain why it matters. Every credibility signal on Executive Profile should be traceable to a real event elsewhere in Executive Path (a milestone reached, a review score received, a document verified) rather than a self-declared claim sitting next to a vanity follower count. Brand Studio and Analytics exist to help a founder communicate that real credibility more effectively — not to manufacture the appearance of it.

Same visual system throughout: `#F59E0B` accent, DM Sans/DM Mono, hairline borders, restrained shadows. This layer introduces one additional convention: a small "Verified" glyph (already used inconsistently today — `AuthorityProfile.jsx`'s `VerifiedBadge` — standardized here to one consistent green check treatment) that appears next to any credibility claim that has a real, auditable source, and nowhere else. An unverified claim is shown in plain text with no badge, not a grey "pending" badge that visually competes with the real one.

## 0.2 Data reality check — read before implementing anything below

**Already real — reuse:**

| Existing field/table | What it provides |
|---|---|
| `profiles` columns: `bio`, `headline`, `linkedin_url`, `github_url`, `portfolio_url`, `website`, `career_timeline`, `education`, `certifications`, `aura_score`, `elo_rating`, `verified`, `verification_state`, `authorityType`, `is_mentor`, `years_of_experience` | Most of Executive Profile's factual content already has a real column — this profile is mostly an assembly/redesign job, not a new-data job. |
| `connections`, `follows` | Real follower/following/connection graph — see the inconsistency flagged below. |
| `notifications` | Real table, already used by Executive Home — Notifications module is an extension (add `category`, `urgency`) not a rebuild. |
| `pulse_posts` engagement counters | Real basis for Content Reach/Engagement in Executive Analytics, and for Brand Studio's "Performance Predictions" once enough historical posts exist to predict from. |
| `SettingsPanel.jsx` | Already a real, working settings screen — handles Account, Delete Account, and explicitly delegates Password/2FA/session management to Supabase Auth / the OAuth provider (documented in its own copy: "2FA setup and session revocation are available through your sign-in provider"). Executive Settings in this spec is an Executive-specific extension of this existing component (adding Startup Access, Team Permissions, API Keys, Integrations sections), not a second settings system. |
| `skill_endorsements` | Real but narrowly skill-scoped — a partial, not exact, fit for Profile's "Recommendations/Testimonials." Worth a short review of whether to broaden this table's scope or add a distinct `testimonials` table before building, rather than assuming either answer. |

**A real inconsistency worth fixing, not designing around:** `profiles` has both integer `followers`/`following` columns AND a real relational `follows` table. These are two sources of truth for the same fact. The design in §1 below reads follower/following counts from `follows` (the real relational source, already used by Executive Home's Network widget) and treats the `profiles.followers`/`following` integer columns as legacy — flagged for cleanup/removal in a future migration, not perpetuated by this new profile design.

**Does not exist — new tables needed:**

| Gap | What's missing |
|---|---|
| Inbox | No messaging/chat table exists anywhere in the codebase today. This is the single biggest build in this entire spec — needs `conversations`, `conversation_participants`, `messages` tables plus real-time delivery (Supabase Realtime channels are the natural fit given the existing stack). |
| Influence Index / Thought Leadership Score | No such computed metric exists. Must be defined as a transparent formula over real inputs (verified milestones, review scores from the Startup Workspace review cycle, content engagement, follower growth rate) before it's shown as a number anywhere — never an opaque AI-invented score. |
| Testimonials/Recommendations (if `skill_endorsements` isn't broadened) | New `testimonials` table: author_id, subject_id, content, relationship_context, verified_via (e.g. tied to a real shared event like a completed mentorship session or investor interaction). |
| Media Kit / Brand Studio content generation and multi-platform publishing | No content-generation or scheduling infrastructure exists; the existing Groq proxy (`backend/server/routes/groqProxy.js`, already used by `CopilotWidget`) is the right reuse target for generation itself, but scheduling/multi-platform publishing needs new tables (`brand_content_drafts`, `content_calendar_entries`) and, for actual multi-platform posting, real OAuth integrations with each target platform — a meaningfully larger scope than the AI-generation piece alone. |
| Profile view tracking, pitch deck view tracking (for Analytics) | No page-view analytics exist yet; needs a lightweight `profile_views` event table, separate from Funding Hub's `pitch_room_visits` (already spec'd there) which Executive Analytics should simply read from rather than duplicating. |

## 1. Executive Profile

Single scroll, editorial pacing (not a form-filled directory card). Hero: cover, avatar, name, headline, Verified glyph (only if `verified`/`verification_state` is genuinely true), a one-line Personal Mission (new, short, founder-authored — deliberately capped short so it reads as a mission statement, not a bio dump). Below the hero, a compact stat strip reading real numbers only: Followers/Following (from `follows`, not the legacy `profiles` integers), Startups (count from Startup Workspace), Influence Index (only rendered once the formula in §0.2 has real inputs to compute from — otherwise an honest "Building your Influence Index — verified milestones and engagement will populate this" empty state, never a fabricated starting number).

Sections below, each collapsible/progressive-disclosure rather than all-expanded-by-default: Vision + Biography (founder-authored, with an "AI Generated Executive Summary" and "AI Generated Biography" as opt-in AI-assisted drafts the founder can accept/edit/discard — never auto-published without review), Founder Journey (built from real `career_timeline` + Startup Workspace's `startup_milestones`, rendered as the same timeline component used in Startup Workspace §8 for visual consistency across the whole Executive Path), Current Startup + Past Companies (real, from `startups`/`career_timeline`), Achievements/Awards/Patents/Publications/Media Coverage/Speaking Engagements/Podcasts/Books/Research (a single unified "Credentials" section, tag-filterable by type, rather than nine separate stacked sections — this is where the "not another LinkedIn profile" test matters most, since LinkedIn's approach of nine stacked sections is exactly what creates the cluttered profile-as-resume feeling this brief rejects), Mentors/Investors/Board Positions/Advisory Roles (relationship chips, each linking to the real counterpart profile), Startup Portfolio + Investment Portfolio + Startup Timeline (cross-references Startup Workspace/Funding Hub directly rather than duplicating that data on the profile), Verified Milestones (explicitly the subset of the Founder Journey that carries the Verified glyph), Recommendations/Testimonials (per §0.2, sourced from real relationship context, never solicited as generic "write me a recommendation" LinkedIn-style requests — instead prompted contextually right after a real shared event, e.g. right after a mentorship session concludes).

Visibility controls: Public Profile / Private Profile toggle (backed by `profile_visibility`, already a real column), Share Profile (generates a real shareable link), Download Profile (exports a clean PDF/one-pager built from the same real data — not a second content system, a rendering of what's already on the page).

## 2. Brand Studio

Two views: **Compose** and **Content Calendar**. Compose is a single, format-aware editor — the founder picks a content type first (LinkedIn Post, Twitter Thread, Blog, Press Release, Founder Story, Launch Announcement, Newsletter, Media Kit, Pitch Script, Email Campaign, Product Update, Hiring Post, Investor Update, Thought Leadership Article) and the editor adapts its structure to that type (a Twitter Thread gets numbered tweet blocks; a Press Release gets a headline/dateline/body structure) rather than one generic textarea for everything. AI features surface as a persistent side panel, not modal interruptions: Generate Content (from a brief prompt or from an existing Executive Profile/Startup Workspace fact, e.g. "turn this milestone into a launch announcement"), Rewrite/Improve Writing (inline, selection-based, Notion-AI-style), Create Visuals (image generation, clearly AI-labeled), Suggest Hashtags, SEO Optimization, Audience Analysis (who on-platform is likely to engage, based on real follow/industry-match data, not invented demographics).

Content Calendar is a real calendar view of scheduled/published content, with Performance Predictions shown only once enough historical `pulse_posts` engagement data exists to predict from honestly — before that threshold, the prediction slot is simply omitted rather than showing a low-confidence guess with false precision. Approval Workflow (for team-authored content going out under the founder's name) is a simple draft → review → approved → scheduled status chain, reusing Team module's existing permission levels from Startup Workspace rather than inventing a new approval-role system. Publishing is explicitly scoped honestly per §0.2: publishing to Executive Feed (`pulse_posts`) is real and immediate; true multi-platform publishing to LinkedIn/Twitter/email requires real OAuth integrations per platform and should be marked "Connect [Platform]" gated features, not implied to work out of the box.

## 3. Executive Analytics

Single scroll of real, sourced charts — this is explicitly not meant to look like a generic BI dashboard; each chart should read as "here's what happened to your credibility and reach," grouped into three bands rather than a flat grid of 19 equally-weighted tiles: **Reach** (Profile Views, Follower Growth, Content Reach, Content Engagement, Website Clicks — the profile-view and website-click metrics need the new tracking table flagged in §0.2; the rest are real today), **Opportunity** (Investor Interest, Startup Visibility, Pitch Deck Views — reads directly from Funding Hub's `pitch_room_visits`, not a duplicate metric; Opportunity Conversion, Partnership Requests, Speaking Invitations, Media Mentions — several of these have no source yet and render as "Coming soon" per the same honesty convention used in every prior spec), **Standing** (Influence Index trend, Thought Leadership Score trend, Mentor Activity, Community Participation, Hiring Performance, Fundraising Progress — each cross-referencing its owning module rather than recomputing independently). Trend charts use simple line/area treatments; a single heatmap is justified for one specific use (posting-time vs. engagement, to inform Brand Studio's publishing schedule) rather than heatmaps used decoratively across multiple metrics. Benchmarks, where shown, compare against anonymized cohort aggregates (e.g. "founders at your stage") — never against a named competitor's real numbers.

## 4. Inbox

The largest net-new build in this spec (see §0.2). Layout: left rail of conversation-type sections (Investor Messages, Mentor Conversations, Advisor Chat, Customer Messages, Government Messages, University Messages, Community Messages, Recruiter Messages, AI Conversations, System Updates, Meeting Invitations, File Sharing) functioning as filters over one underlying `conversations` table (a `counterpart_type` column drives the section, not eleven separate tables) plus Search, Pinned, Archived, Unread as cross-cutting views rather than additional sections. Conversation view: standard thread layout, with an AI panel offering Summaries (of long threads), Suggested Replies (draft, never auto-sent), Action Items (extracted, checkable, feeding the same Tasks concept used on the Startup Workspace/Funding Hub dashboards), Follow-up Reminders, Conversation Insights (sentiment/urgency read, used to help prioritize which threads need attention, feeding into Notifications' prioritization in §5). "AI Conversations" is the one section that's actually the existing `CopilotWidget` history rather than a new conversation type — surfaced here so a founder has one place to find every conversation, real or AI, rather than the AI assistant living in a totally separate mental bucket.

## 5. Notifications

Extends the real `notifications` table (add `category`, `urgency`) rather than a new system. Categories: Investor Activity, Mentor Feedback, Grant Alerts, Funding Updates, Startup Milestones, Hiring Activity, Community Activity, Event Reminders, Market Alerts, Government Schemes, Research Updates, Speaking Invitations, Media Mentions, AI Recommendations. Urgency levels (Critical/Important/Normal) drive visual weight, not notification volume — Critical notifications interrupt (a small persistent banner until acknowledged), Important surface in the main feed with a colored left-edge, Normal are list rows with no special treatment. AI prioritization means the default sort is relevance-weighted, not strictly chronological, with a manual "Newest first" toggle always available so the founder never feels the AI is hiding something by re-ordering silently. Daily/Weekly Digest is a single scheduled summary email/in-app card, generated from the same underlying notification stream rather than a separately-maintained digest content system.

## 6. Executive Settings

Explicitly an extension of the existing, real `SettingsPanel.jsx` — Account, Privacy, Notifications, Language, Appearance, Connected Accounts, Billing/Subscriptions, Export Data, and Delete Account sections already exist there and should not be rebuilt. Net-new sections specific to the Executive path: AI Preferences (tone/verbosity defaults for Brand Studio and the Copilot, model-agnostic — never expose which underlying model is used), Startup Access + Team Permissions (surfaces the same permission levels used in Startup Workspace's Team module, edited from one place rather than duplicated), Integrations (calendar, email, social publishing connections — each an explicit "Connect" flow, honestly showing "Not connected" rather than implying integrations exist before they're built), API Keys (only relevant once Executive Path exposes any external API — flagged as not yet applicable rather than speculatively designed), Audit Logs (real, if `org_audit_log`'s pattern is extended to non-institution accounts — worth checking whether that table's schema can generalize before building a parallel log).

## 7. Ecosystem integration — making the loop visible

The brief's example loop (publish launch announcement → followers see it in Executive Feed → investors receive updates → analytics measure engagement → AI recommends improvements → brand grows → Influence Index increases → new partnership opportunities appear) is the same integration principle as the Ecosystem Layer's Journey Trail (see `ECOSYSTEM_LAYER_DESIGN_SPEC.md` §6) applied to the identity/brand loop specifically. Recommended implementation: rather than a second parallel trail component, Brand Studio's Content Calendar entries and Executive Analytics both link into the same Journey Trail component already spec'd — a published announcement becomes one entry, its resulting engagement/Influence Index delta becomes a linked follow-up entry, and any Partner Hub or Funding Hub opportunity that cites the announcement as context (e.g. an investor's `investor_interactions` row referencing that specific `pulse_posts` id) appears as the next entry. One trail, fed by every module, rather than five modules each claiming their own version of "and then this led to that."

## 8. Implementation phasing (recommended order)

1. Executive Profile rebuild — fixes the actively-broken `AuthorityProfile.jsx` and is mostly an assembly job over already-real `profiles` columns; highest urgency, lowest new-schema cost.
2. Notifications extension (`category`/`urgency` columns on the real `notifications` table) — small, immediately useful, no dependency on anything else in this spec.
3. Executive Settings extension — additive sections on top of the already-real `SettingsPanel.jsx`.
4. Executive Analytics, Reach band only (Profile Views needs the new tracking table; Follower Growth/Content Reach/Engagement are real today) — ship the real bands, hold the Opportunity/Standing bands until Funding Hub and the Influence Index formula exist.
5. Influence Index / Thought Leadership Score formula definition — a data/product decision that should be written down and reviewed before it appears as a number anywhere, not an implementation detail decided inside a component.
6. Brand Studio, Compose + Executive Feed publishing only (reuses the real Groq proxy and `pulse_posts`) — hold multi-platform publishing until real per-platform OAuth integrations are built.
7. Inbox — the largest net-new build in this entire spec (`conversations`/`messages` + realtime delivery); sequenced last deliberately, since it's the one module here with no partial-reuse path and the highest engineering cost relative to the other five.
