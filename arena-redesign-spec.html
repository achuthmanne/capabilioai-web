03 · Visual Hierarchy

What is Primary, Secondary, Tertiary

Hierarchy Layers

1
ELO Score + Tier Badge

Largest number on screen in the sidebar. It's the student's currency. Always in view.

2
Challenge Title + Difficulty

Bold, high-contrast title. Difficulty tag uses colour-coded pill — green/amber/red.

3
Submit Button + Timer

Orange CTA dominates the action area. Timer in monospace beside it — always visible.

4
Topic Tags + ELO Gain

Small pills in muted tones. ELO gain in green mono. Reward visible before solving.

5
Attempt Count, Company Tag

Tertiary metadata. Shown on hover or in collapsed form. Never competes with primary.

Two Sum

Easy Array Hash Map 👥 4.2k solved

Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.

You may assume that each input would have exactly one solution, and you may not use the same element twice.

Example 1

Input: nums = [2,7,11,15], target = 9 Output: [0,1] Reason: nums[0] + nums[1] == 9

Example 2

Input: nums = [3,2,4], target = 6 Output: [1,2]

Constraints

2 ≤ nums.length ≤ 10⁴ -10⁹ ≤ nums[i] ≤ 10⁹ Only one valid answer exists.
Auto-save ✓
class Solution: def twoSum(self, nums: List[int], target: int) -> List[int]: # HashMap approach — O(n) time, O(n) space seen = {} for i, num in enumerate(nums): complement = target - num if complement in seen: return [seen[complement], i] seen[num] = i
Test Results
Test 1: [2,7,11,15], 9 → [0,1] ✓
Test 2: [3,2,4], 6 → [1,2] ✓

11 · Supabase Data Model

Database Schema Recommendations

Four tables to add / modify. Existing challenges table stays as-is. RLS on all tables — students only read their own rows.

challenge_attempts — ELO + recruiter timestamps

ColumnTypeKeyNotes
iduuidPKgen_random_uuid()
user_iduuidFK → usersauth.uid()
challenge_iduuidFK → challenges
started_attimestamptzIDXWhen student opened the problem
submitted_attimestamptzIDXRecruiter-visible timestamp
statustext'solved' | 'attempted' | 'timed_out'
scoreinteger0–100
elo_beforeintegerELO snapshot before attempt
elo_deltaintegerPositive or negative delta applied
duration_secsintegerSolve time in seconds
languagetext'python' | 'javascript' | 'sql' etc.
is_recruiter_visiblebooleanDefault true. Student can hide individual attempts.

elo_history — audit trail for ELO changes

ColumnTypeKeyNotes

user_iduuidFK → users IDX

Use a Postgres trigger on challenge_attempts insert to auto-write to elo_history and update users.elo_rating atomically.

leaderboard_cache — pre-computed rankings (refresh hourly)

ColumnTypeKeyNotes

Don't compute rank on every page load — use a pg_cron job to refresh this table every hour. Query is just a SELECT from this table, never an ORDER BY on raw data.

ELO Algorithm — Recommended Formula

-- ELO delta calculation (server-side, in edge function)
-- K = 32 for students (more volatile, faster growth)
const K = 32
const expected = 1 / (1 + Math.pow(10, (opponentElo - userElo) / 400))
-- actual = 1.0 if solved, 0.5 if partial, 0.0 if failed/timeout
const delta = Math.round(K * (actual - expected))

-- opponentElo = difficulty proxy:
-- Easy → 500, Medium → 750, Hard → 1050
